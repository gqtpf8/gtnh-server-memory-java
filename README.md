## GTNH 服务端到底吃多少内存

按官方公式换算，人数和内存的对应关系是这样的：

| 同时在线 | 前期（LV–HV） | UV 级以后 |
| --- | --- | --- |
| 1 人 | 6GB | 6GB |
| 4 人 | 7.5GB | 9GB |
| 6 人 | 9GB | 11GB |
| 10 人 | 10.5GB | 15GB |

这里是分给 Java 的堆内存，不是整机内存。整机还要留 1–2GB 给系统和其他进程，所以 10 人进 UV 的服，机器至少 16GB 内存才不勉强。

容易忽略的是默认启动脚本。手动搭的服务端里，`startserver-java9.sh` 第 7 行写死了 `-Xms6G -Xmx6G`，也就是不管你的机器是 8GB 还是 32GB，服务端只拿 6GB。4 个人前期勉强够，6 个人开始就会出现周期性的卡顿和加载延迟，10 个人基本是直接崩。改这一行是开服后第一件该做的事，改完再启动。

至于为什么有的公共服直接上 128GB：像 StoneLegion 那种常年不删档、几十人同时在线的服，用的是 Core Ultra 9 285K、128GB DDR5 6400、两块 4TB NVMe Gen4 加 UPS。这跟你和三个朋友周末开荒不是一个量级的需求，不必照抄。

算完人数，回到套餐表对一下：3 人以内选 4 核 8GB 就够，6 人以上直接看 6 核 12GB。

## 路线一：Linux 手动搭

适合想把服务端攥在自己手里、愿意用命令行的人。以 Ubuntu 24.04 为例，全程 root 权限操作。

1. `apt update -y && apt upgrade -y` 更新系统
2. `apt install openjdk-21-jre-headless unzip -y` 装 Java 和 unzip。官方推荐 Java 17+，这份指南实际用的是 Java 21，跑 2.8.x 没问题
3. 从 GTNH 官方下载页取 Java 17+ 版本的服务端包，用 `wget` 拉到服务器上
4. `unzip` 解压到 `GTNH-Server` 目录
5. 编辑 `startserver-java9.sh`，把内存改成机器实际能给的量
6. `chmod +x startserver-java9.sh` 加执行权限
7. `echo "eula=true" > eula.txt` 接受 EULA
8. `screen -R MC` 开一个会话，在里面执行 `./startserver-java9.sh`

第 8 步之后要等**至少 5 到 10 分钟**服务端才算起来。GTNH 加载的模组数量摆在那里，进度条走得慢是正常的，不是卡死，别急着 Ctrl+C 重来。

用 `screen` 是为了断开 SSH 后服务端继续跑。`CTRL+A` 再按 `d` 脱离会话，`screen -r MC` 重新进去。

关服有讲究：先在游戏里执行 `/stop`，服务端会开始 12 秒倒计时，在倒计时结束之前按 `CTRL+C`。等它自己走完，配置文件会处于占用状态，改了不生效。

起来之后加白名单：`/whitelist add 玩家名`。

想改玩法的话，几个常用开关：

- `config/GregTech/Pollution.cfg` 里把 `B:"Activate Pollution"=true` 改成 `false`，关掉污染
- `serverutilities/serverutilities.cfg` 里 `B:enable_backups=false` 改 `true` 开自动备份
- 同一个文件里 `ranks { B:enabled=false }` 改 `true`，`world { B:chunk_claiming` 和 `B:chunk_loading` 也改成 `true`，家、区块加载、圈地才能用
- 再编辑 `serverutilities/server/ranks.txt`，给 `[player]` 加上 `default_op_rank: true`，删掉 `[vip]` 和 `[admin]`

GTNH 改过 `server.properties` 的默认值：`LEVEL_TYPE=rwg`、`DIFFICULTY=hard`、`ALLOW_FLIGHT=true`、`ENABLE_COMMAND_BLOCK=true`。这些是整合包按自己的平衡调过的，除非你清楚后果，否则别动。

## 路线二：Docker 一条 `TYPE` 搞定

手动搭一次要十几分钟，Docker 部署把下载、安装、更新都包了。itzg/docker-minecraft-server 这个镜像内置了 GTNH 专用类型，把环境变量 `TYPE` 设为 `GTNH`，剩下的交给它。

关键的环境变量：

- `TYPE=GTNH`
- `GTNH_PACK_VERSION`：`latest` 选最新正式版并在每次启动时自动更新；`latest-beta` 只选 beta 或 RC；填具体版本号（比如 `2.8.1`）则完全手动控制。官方推荐第三种
- `GTNH_DELETE_BACKUPS=false`：默认不删升级备份
- `SKIP_GTNH_UPDATE_CHECK=false`：默认会做更新检查

Java 版本按镜像支持情况走 17+，2.8.0 之后的版本上 Java 25。端口映射两个：游戏用 `25565`，开了网页地图再放 `8123`，浏览器直接访问就能看世界地图。

还有个开发版通道，`GTNH_USE_DAILY_BUILD=true` 配合 `GTNH_PACK_VERSION` 设为 `latest` 或具体 workflow run ID，另外需要配一个有 `public_repo` 权限的 GitHub Token 才能下载。官方自己写明这些每日构建不稳定、可能带 bug，生产服别碰。社区里也有人维护现成的 GTNH 镜像，分 stable 和 daily 两个 tag，内置备份回滚，但作者本人都说别依赖那套备份，自己另外备一份更稳妥。

两条路线怎么选：只开一个 GTNH 服、想少折腾，走 Docker；要同时跑多个服务端、要装别的服务、或者习惯自己控制每个文件，走手动。两者对机器的最低要求一样。

## 四个容易出问题的坑

**第一，`latest` 会在你不知道的时候升级，并替换全部配置。** 版本升级时服务端会把 config 目录整个换成新版本的默认值，保证新功能正常。你之前调过的污染开关、备份开关、圈地设置全部回到出厂状态。旧配置会存到数据目录下一个以 `gtnh-upgrade-` 开头、带时间戳的文件夹里，需要你手动比对重新应用。长期开的服一定要把 `GTNH_PACK_VERSION` 固定成具体版本号。

**第二，`GTNH_DELETE_BACKUPS=true` 会在每次启动时删掉所有备份文件夹。** 就是上面说的那些 `gtnh-upgrade-` 目录。硬盘紧张的时候有人会顺手打开它，然后某次升级出问题，连回滚用的旧配置都找不回来了。

**第三，Forge 的确认提示会永久删方块。** 启动时如果 Forge 停下来问你确认，通常意味着它检测到了缺失的注册表项，多半是模组被删、被禁用，或者升级后某些方块、物品、实体、流体不存在了。加 `-Dfml.queryResult=confirm` 到 `JVM_OPTS` 能自动确认跳过这个提示，但确认之后 Forge 会扫描世界文件，把属于缺失模组的方块、物品、区块加载实体和流体**永久删除**。这一步不可逆，存档里那些机器和管道会直接消失。遇到这个提示，正确的做法是先查清楚是哪个版本变更导致的，别急着点确认。

**第四，`SKIP_GTNH_UPDATE_CHECK=true` 会连首次安装一起挡掉。** 这个变量的作用是彻底禁止更新检查，但新机器上它同样会阻止服务端下载安装，结果就是容器起来了、目录是空的。只能等第一次装完再设。

另外两个不算坑但会让人误判的：默认只给 6GB 堆内存，人一多就不够；首次启动要等 5 到 10 分钟。这两件事加起来，就是大部分人以为“开服失败”的真实原因。

怕配置被升级覆盖、想自己控制版本节奏的，用带 root 权限的 VPS 更合适，随时能停容器、拷存档、改回旧版本。

## 不想自建：公共服清单

官方服一共五个，全部在欧洲，全部需要白名单：Delta、Epsilon、Eta 三个长期服，一个每日构建的 Iota，一个测试服 Zeta。白名单意味着你得先加他们的社区渠道申请，不能直接连。

非官方服选择多一些，按地区记：

- **北美**：Apocalyptic Gaming Network（无白名单）、Prospercraft、StoneLegion 的 2027 / 2026 / 2025 三个服（加拿大，均无白名单，2021 那个老服要白名单）
- **欧洲**：Craftersland（德国）、ValhallaMC（无白名单）、The Penguin Network（德国）、Pumpkin Keep（荷兰，白名单）、StoneHuts（白名单）、KineticNexus（白名单）
- **多地区**：Modded Minecraft Club 有美洲+澳洲、欧洲+亚洲多条线路，另外还有两组禁止传送的 MMC 服
- **俄语区**：Zvezdolet（俄英双语，白名单）

StoneLegion 那套服值得一提：从 2021 年开到现在的老存档没删过档，社区规则里明确要求离别人的基地 400 格以上，备份做了本地、远程、云三份，一天多次。这类长期服的稳定性靠的是硬件和运维习惯，不是配置多高。

这份列表最后一次更新是 2026 年 5 月 31 日，公共服的开关状态变得比版本还快。进服之前去 GTNH 官方 wiki 的公共服务器页确认一遍，上面标了 Closed 的就别试了。挑服的时候看三件事：所在地区（欧服延迟对国内不友好）、要不要白名单、跑的版本是不是你客户端能连的。

## 最后怎么定

- **1–2 人，先试试水**：雨云 2 核 4GB（112 元/月，9950X 宿迁）够跑前期，但要把 `-Xmx` 调到 3.5G 左右，网页地图先别开。预算允许就直接上 4 核 8GB，省得玩到一半要迁移存档
- **3–6 人长期玩**：4 核 8GB 是甜点，200 元/月那档配 150GB 硬盘，备份随便存。CPU 单核性能比核心数重要，Minecraft 的主循环压在一个核上，9950X 和 14900K 这类高主频机型比同价位的多核服务器更合适
- **8 人以上或已经进 UV**：6 核 12GB，内存按每人 1GB 往上加。这个阶段机器一多，区块加载和实体运算都会涨，别指望靠调参数省内存
- **不想管服务器**：直接去公共服，欧服要白名单、北美不用，先玩两周再决定要不要自己开

下单前把这几件事确认掉：CPU 具体是哪款（页面会写机型，别只看核数）、硬盘够不够放整合包和备份、NAT 端口数够不够你开服加网页地图、续费价是多少（首月 5 折只覆盖第一个月，长期开选年付 7 折更实在）、退款条件（7 天内自助退订，每账号 3 次，领了返利积分或超时就不能退，日付产品不支持退订）。
